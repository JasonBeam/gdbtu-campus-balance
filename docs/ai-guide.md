# 用 AI 帮你上手校园余额

不熟悉 Python、Scriptable 或配置文件，也可以让 AI 带着你逐步操作。建议按“读项目 → 跑演示 → 自己填写参数 → 核对结果”的顺序进行。

**AI 辅助是可选的，不是项目运行依赖。** 小组件和面板本身不调用 AI API，不需要填写 AI API Key；你选择的 AI 工具可能有自己的账户、订阅或使用限制。

[返回首页](../README.md) · [个人参数提取教程](setup.md)

## 先选合适的方式

| 方式 | 适合你做什么 | 操作由谁完成 |
| --- | --- | --- |
| 普通 AI 聊天 | 理解教程、拆解步骤、分析脱敏报错 | 你在终端、浏览器和手机上操作 |
| 本机代码助手，例如 Codex | 读取公开源码、检查运行环境、运行演示、检查改动 | 助手在你授权的本机环境中操作；登录和个人参数由你处理 |

普通聊天未必能打开 GitHub 链接；本机代码助手也未必能控制你的手机。先确认实际能力，不把 AI 说“已完成”当作设备上已经成功。

下文提示词可以直接复制。将 `【方括号内容】` 换成你的设备、目标或错误描述。

## 第一步：让 AI 先读当前项目

### 只有聊天窗口

发送项目地址和下面这段：

```text
我想使用这个校园余额项目：
https://github.com/JasonBeam/gdbtu-campus-balance

我的设备是【例如 iPhone / macOS / Windows】，目标是【桌面小组件 / 电脑面板】。
请先阅读 main 分支的 README.md、docs/setup.md、docs/ai-guide.md。
如果无法访问链接，请告诉我需要粘贴哪些公开文档，不要假装已经读过。

请用中文分步骤带我操作：每一步给出操作位置、需要输入的内容和预期结果。
先演示，后接入个人账户。不要向我索取真实登录凭据或完整个人配置。
请区分当前已验证的功能与仍待验证的流程，不要承诺免抓包或自动续期。
```

若 AI 不能读取链接，从 GitHub 打开上述公开 Markdown 文档，复制内容给它即可。不要用自己的 `config.local.json` 代替文档，也不要上传私人截图或抓包来补充上下文。

### 使用本机代码助手

先从 GitHub 下载源码 ZIP 并解压，或克隆仓库，再在助手中选择包含 `README.md` 和 `server.py` 的项目文件夹。随后发送：

```text
请帮我在本机运行 gdbtu-campus-balance。
先读取 README.md、docs/setup.md、docs/ai-guide.md、config.example.json 和 .gitignore。
仅检查公开源码和运行环境；不要读取 config.local.json、private/、Keychain、
原始抓包或其他个人目录，不做包含这些目录的全文扫描。

1. 检查 Python 是否满足 3.10+，给出适合当前系统的命令。
2. 检查当前目录和 4186 端口；端口被占用时不要结束其他进程。
3. 使用 --demo 启动服务，确认页面显示演示数据，不访问学校接口。
4. 汇报实际执行的命令、访问地址、验证结果，以及尚未验证的事项。

如果需要安装软件、修改系统设置或开放网络监听，请先说明原因与具体改动。
演示阶段不要创建或覆盖个人配置，不要提交或推送任何文件。
```

提示词是操作约束，不能替代工具本身的文件权限控制。优先在尚未放入真实凭据的源码目录中完成演示；不要给不需要处理个人数据的助手额外目录访问权。

## 第二步：先跑通演示

### iPhone：先确认小组件能显示

```text
我想先在 iPhone 上预览这个项目，不接入真实账户。
请按当前 README 指导我下载 Scriptable 单文件、导入并运行。
让我选择“预览演示数据”；再指导我添加桌面小组件，选择脚本，组件参数填 demo。
说明成功时应该看到什么；不要让我提供 acc_token 或更改现有脚本的 Keychain。
如果你不能操作手机，只给我明确的手动步骤，不要说已经替我安装。
```

预期结果：脚本能显示校园余额演示卡片，桌面组件也能选择对应脚本。这里的金额是演示数据，不能用来判断账户接口是否有效。

### 电脑：先确认面板能打开

在包含 `server.py` 的项目文件夹运行：

```bash
# macOS / Linux
python3 --version
python3 server.py --demo
```

Windows 若已安装 Python，可在 PowerShell 中检查并运行：

```powershell
py -3 --version
py -3 server.py --demo
```

确认输出的版本为 3.10 或以上。没有对应命令时，先处理 Python 安装或命令路径；不要为了启动面板安装随机依赖。本项目无需 `pip install`。

浏览器打开 <http://127.0.0.1:4186>，应显示“示例数据”模式和演示走势图。终端服务需要保持运行；停止时在该终端按 `Ctrl+C`。

如果默认端口被占用，可使用项目现有参数：

```bash
python3 server.py --demo --port 4188
```

Windows 对应使用 `py -3 server.py --demo --port 4188`。此时访问 <http://127.0.0.1:4188>，无需修改代码或关闭其他服务。

## 第三步：个人参数由你自己取得和填写

此时切换到[配置提取教程](setup.md)。先在官方页面登录、选择自己的宿舍并确认余额正确，再尝试本机导出；不支持该方法时，查看抓包备用步骤。

AI 可以解释这些字段，但不要让它猜值：

| 字段 | 你需要知道什么 |
| --- | --- |
| `syscustid` / `custid` | 两种不同的用户、校园卡账户标识，不能互换 |
| `buildingID` | 官方电费页面最终选中的宿舍节点；文字楼栋、楼层和房号不能直接替代 |
| `acc_token` | 真实登录凭据，可能过期；不要粘贴给 AI |
| `areacode` | 以自己的官方会话为准，不能让 AI 根据校名猜值 |

只需要理解字段时，可以这样问：

```text
请根据 config.example.json 和 docs/setup.md 解释配置字段。
不要向我索取实际值，不要猜测学校接口或宿舍 ID。
我要由自己在本机填写 config.local.json，或在 Scriptable 中导入配置。
请说明每个字段的用途、必填条件，以及如何用官方页面核对。
```

填写完成后：

- **iPhone**：在 Scriptable 中选“导入官方页面配置”，随后选“查询并预览”。如果桌面组件仍填了 `demo`，清空该参数才能查看自己的数据。
- **电脑**：停止演示服务，再运行 `python3 server.py`，Windows 使用 `py -3 server.py`。配置默认位于项目根目录的 `config.local.json`。在浏览器切换“真实数据”，或打开 <http://127.0.0.1:4186/?mode=real>；自定义端口时使用对应地址。

凭据仍由程序发给学校接口完成查询，不需要发给 AI。官方页面只在微信内有效时，不要让 AI 声称能自动把会话迁移到 Safari。

## 第四步：让 AI 根据脱敏信息排错

先描述“哪一步失败、看到什么”，不必发送全部日志。终端和截图里若有用户名路径、登录链接、Token、学号、宿舍、真实余额等个人信息，先去掉。

```text
我在使用 JasonBeam/gdbtu-campus-balance，遇到以下问题。

系统：【例如 macOS / Windows / iOS】
使用方式：【源码 / v0.1.0 下载包 / Scriptable】
失败阶段：【启动演示 / 打开页面 / 导入配置 / 查询真实余额】
执行命令或菜单：【不含个人参数】
脱敏后的错误：【例如 端口被占用 / 登录凭据已失效 / 接口未返回有效余额】
官方页面能否查到同一账户、同一宿舍：【能 / 不能 / 尚未检查】

请先根据当前公开源码定位最可能的原因，给出一个最小检查步骤。
不要索取个人配置、Cookie、Keychain、Token 或原始抓包。
不要以关闭 HTTPS 校验、扩大监听地址或伪造余额作为修复。
如果证据不足，请说明缺少哪类脱敏信息，不要编造接口字段。
```

| 现象 | 优先检查 |
| --- | --- |
| 找不到 `server.py` | 终端是否在正确的解压目录，ZIP 是否多套了一层文件夹 |
| Python 命令不存在或版本不足 | 当前系统是否装好 Python 3.10+，使用了哪个解释器 |
| 端口被占用 | 尝试 `--port 4188`，不结束无关进程 |
| 面板一直显示演示金额 | 服务是否仍有 `--demo`，页面是否仍在示例模式 |
| 小组件一直显示演示金额 | 桌面组件参数是否仍填了 `demo` |
| 登录凭据失效 | 先检查官方页面，再由自己重新登录、导出并导入配置 |
| 一项余额缺失或显示缓存 | 电费与校园卡分别核对；不要用另一项成功证明两项都正常 |
| 校园卡没有历史记录 | 学校接口可能没有返回更新时间；项目不会为此补造记录 |

若要提 GitHub Issue，可以让 AI 依照[仓库问题模板](../.github/ISSUE_TEMPLATE/)整理以上信息，发出前再检查一次是否包含个人数据。

## 想让 AI 调整界面？先限制改动范围

```text
请只调整这个项目的【具体文案或显示细节】。
沿用当前点阵小组件和 Dashboard 样式，不重新设计整体布局。
不要改变学校请求、认证、字段解析、缓存、刷新频率或记录语义。
不要读取或修改个人配置、旧脚本、Keychain 和已有历史数据库。
在独立分支修改，展示差异并运行与改动相关的检查；不要自动发布或推送。
如果调整必须涉及查询逻辑，请先说明原因，再讨论实现。
```

需要检查数据逻辑时，仓库提供以下离线测试，不要求学校账户：

```bash
python3 -m unittest discover -s tests -v
node tests/test_scriptable.cjs
node tests/test_export.cjs
```

后两项需要 Node.js；普通使用者运行电脑面板不需要 Node.js。自动测试通过也不能替代真实学校登录和 iPhone 检查。

## 最后由你核对这几件事

- 演示模式能打开，且明确显示为示例；查看个人数据时，已退出演示模式。
- 每项余额与官方页面的同一账户、同一宿舍对应；没有返回的值显示为缺失或缓存。
- 学校更新时间与本机查询时间没有混用，余额变化没有被描述为消费账单。
- 没有向 AI、GitHub 或公开截图发送个人配置和凭据。

截至本教程整理时，独立版真实账户查询、微信内导出、Medium 实机布局和系统后台刷新仍待完整验收，详见[稳定版验收计划](ROADMAP.md)。AI 可以帮助你完成步骤和整理证据，不能把这些待验证项直接改写成“已支持”。

使用 Codex 的读者可另外参考 [OpenAI 官方 Codex 使用建议](https://learn.chatgpt.com/guides/best-practices)。本教程只说明如何用 AI 辅助本项目，不要求特定模型、订阅或额外插件。
